Sequence 01

Autentikasi Pengguna & SIAKAD

Proses autentikasi dimulai ketika Aktor menginputkan username dan password pada antarmuka LoginForm, yang kemudian meneruskan request authenticate ke Control Class AuthController. AuthController mencari data pengguna melalui Entity User dan memanggil SIAKAD API eksternal untuk memvalidasi status akademik. Dalam blok kondisi (alt), jika kredensial dan status valid, sistem akan men-generate Sanctum Token dari Entity User dan mengarahkan pengguna ke Dashboard utama. Sebaliknya, jika gagal, sistem akan mengembalikan pesan error autentikasi ke layar pengguna.

Sequence 02

Transaksi Top-Up Midtrans

Penumpang memulai pengisian saldo melalui WalletView. WalletService menangani request ini dengan mengecek/membuat data di Entity Wallet, lalu meminta pembuatan transaksi ke MidtransAPI untuk mendapatkan URL Snap. Setelah mencatat transaksi pending di Entity WalletTransaction, URL Snap dirender ke layar penumpang. Saat proses pembayaran selesai, MidtransAPI mengirimkan payload webhook ke WalletService. Di dalam blok kondisi, jika status pembayaran adalah Settlement, sistem meng-update status transaksi menjadi SUCCESS dan melakukan increment saldo di Entity Wallet, lalu mengembalikan respons HTTP 200 OK.

Sequence 03

Request Generate Tiket QR

Penumpang meminta pembuatan tiket dengan menekan tombol pada TicketingView. PaymentBoardingService memanggil Entity Wallet untuk mengecek saldo berjalan. Terdapat blok pengecekan kondisi ganda (alt): jika penumpang adalah mahasiswa reguler dan saldonya kurang dari Rp 7.500, sistem melempar exception dan menampilkan pesan error. Namun, jika saldo cukup atau berstatus Langganan, sistem membuat token UUID dengan durasi aktif (TTL) 5 menit pada Entity BoardingTransaction, lalu mengembalikan token beserta warna bingkai untuk dirender pada layar penumpang.

Sequence 04

Validasi Jarak & Potong Saldo

Pengemudi memindai QR Token melalui ScannerView. Request dikirim ke PaymentBoardingService yang pertama-tama mengecek kapasitas di Entity Fleet. Jika kapasitas penuh, sistem menolak. Jika kursi tersedia, sistem menghitung jarak Haversine. Dalam sub-kondisi, jika jarak lebih dari 15 meter, sistem melempar error Fake GPS. Jika kurang dari 15 meter (Valid), sistem memvalidasi token di Entity BoardingTransaction, mengeksekusi Lock-For-Update dan pemotongan saldo di Entity Wallet, mengubah status tiket menjadi SUCCESS, mengurangi kuota kursi, dan mengembalikan respons sukses.

Sequence 05

Pencatatan Tiket Darurat (Fallback)

Saat terjadi kendala, pengemudi memilih mode darurat pada EmergencyScannerView dan menginputkan NIM. BoardingController menerima data ini dan memanggil fungsi findByNIM pada Entity User. Pada blok alternatif, jika pengguna tidak dikenali, controller melempar pesan error dan menolak akses. Jika pengguna terdaftar, sistem langsung mencatat pemotongan tertunda (pending deduction) pada Entity BoardingTransaction dan mengembalikan pesan sukses agar konfirmasi evakuasi penumpang tercatat.

Sequence 06

Transmisi Sinyal Alarm SOS

Pengemudi menginisiasi peringatan dengan menggeser slider SOS, yang memicu fungsi triggerSos pada DriverController. Controller seketika memperbarui status pada Entity Fleet menjadi OFFLINE_EMERGENCY dan membekukan seluruh transaksi tiket pada armada terkait. Kemudian, event broadcast dikirimkan ke Boundary AdminDashboardView yang langsung memicu alarm audio dan indikator merah berkedip untuk Administrator. Proses berujung pada pengembalian konfirmasi ke perangkat pengemudi.

Sequence 07

Eksekusi Wake-Sleep Cron Job

Aktor Auto-Scheduler (Cron Job) menembakkan trigger waktu tepat pada pukul 10:00:00 ke SchedulerController. Controller merespons dengan memanggil WebSocketReverb eksternal untuk memutus semua koneksi pengemudi, mengubah status sistem menjadi HIBERNATION_MODE, dan mengirim balasan. Setelah jeda waktu istirahat (10:00 - 15:30), Auto-Scheduler kembali mengirimkan trigger. SchedulerController mengeksekusi perintah pembukaan kembali port WebSocketReverb, menetapkan status sistem menjadi ACTIVE_SHIFT, dan memberikan konfirmasi bangun ke sistem penjadwalan.
