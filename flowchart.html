Dashboard Use Case Activity Sequence Flowchart
Flowchart 01

Algoritma Geo-Validation (Boarding)

Alur komputasi dimulai saat sistem mengekstraksi UUID dari QR Token. Sistem pertama-tama memverifikasi kapasitas kursi; jika penuh, transaksi ditolak. Jika tersedia, sistem mengalkulasi jarak antara koordinat GPS pengemudi dan penumpang menggunakan algoritma Haversine. Jika jarak spasial lebih dari 15 meter, transaksi ditolak sebagai indikasi Fake GPS. Apabila valid, sistem menarik meta-data mahasiswa: membebaskan tagihan (Rp 0) untuk kelas karyawan, atau mengecek kecukupan saldo untuk reguler. Logika berujung pada eksekusi Lock-For-Update di pangkalan data untuk memotong saldo, mencatat mutasi, memperbarui tiket, mengurangi sisa kursi, dan memancarkan sinyal ke ponsel penumpang.

Flowchart 02

Algoritma Webhook Midtrans

Sistem otonom ini bereaksi ketika menerima HTTP POST Webhook dari server Midtrans. Peladen akan mengekstraksi Order ID dan mengkalkulasi Hash Signature untuk memvalidasi keaslian permintaan. Jika tidak valid, sistem mengabaikan permintaan (HTTP 403 Forbidden). Jika valid, data ditarik dari pangkalan data; apabila transaksi sudah berstatus SUCCESS sebelumnya, sistem mendeteksinya sebagai webhook duplikat. Jika belum selesai, sistem membedah parameter transaction_status. Status settlement atau capture akan memicu pembaruan transaksi menjadi SUCCESS dan penambahan saldo penumpang. Status cancel atau expire akan membatalkan transaksi.

Flowchart 03

Algoritma Mitigasi Darurat SOS

Algoritma kedaruratan ini dipicu saat peladen menerima sinyal SOS dari perangkat pengemudi. Sistem mengekstraksi ID Armada, lalu memodifikasi tabel armada dengan mengubah statusnya menjadi OFFLINE_EMERGENCY. Untuk membekukan proses boarding, sistem mengeset sisa kursi pada armada tersebut menjadi 0. Sistem kemudian memeriksa antrean transaksi; jika terdapat tiket yang masih menggantung (pending), sistem otomatis membatalkannya dan mengeksekusi refund pengembalian saldo. Terakhir, sistem membentuk payload notifikasi untuk dikirimkan melalui WebSockets, yang menyalakan alarm audio dan visual pada Dasbor Admin.

Flowchart 04

Algoritma Auto-Scheduler

Logika otomatisasi ini berjalan konstan dengan mengecek waktu server setiap detak menit. Jika waktu menunjukkan tepat pukul 10:00 WIB, algoritma memicu Mode Hibernasi: memutus paksa koneksi WebSockets pengemudi, menghentikan listener GPS, dan mengubah status peta penumpang menjadi "Armada Istirahat". Jika waktu menunjukkan pukul 15:30 WIB, algoritma memicu Mode Aktif (Wake Up): membuka kembali port listener WebSockets, menembakkan sinyal ping ke aplikasi pengemudi, dan mengembalikan status peta menjadi "Tracking Aktif". Jika waktu belum menyentuh kedua jadwal tersebut, sistem mengabaikan pengecekan.
